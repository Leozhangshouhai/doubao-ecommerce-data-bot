# 新号安装与验收 SOP（技术版）

> 用途：在**全新账号 + 全新环境**上，从零装到四张报表全部跑通，逐项打勾验收。
> 适用对象：技术接口人（不是老板）。老板版的日常使用说明见 `老板使用SOP.md`。
> 版本 v1.0 / 2026-11-09

---

## 0. 先搞清一件事：仓库给什么，你自己给什么

这个技能**故意不包含任何连接凭据**，所以它分两块：

| 东西 | 从哪来 | 作用 |
|---|---|---|
| 技能本体（SKILL.md + 8 个脚本 + 4 个 SQL 模板 + 样式契约） | **GitHub 仓库**，装的时候自动拉 | 机器人的"脑子"：口径、算法、样式 |
| `ecommerce_bot.yaml` | **你单独发给老板**，仓库里没有 | 机器人的"钥匙"：连接凭据 + 客户名 |

**为什么不在仓库里**：文件里含数据库密码，推到公开/私有仓库都等于把钥匙挂在门上。历史提交里也剔除过这个文件（`filter-branch` 重写过历史），所以远端任何位置都不该出现它。

**影响**：装完技能、不传 yaml，机器人能回答"你是谁""有几个报表"，但**出不了任何报表**——它会明确告诉你"没有配置文件"。这是设计如此，不是装坏了。

---

## 1. 装之前：三个前置条件

| # | 条件 | 怎么确认 | 不对会怎样 |
|---|---|---|---|
| 1 | 豆包在**「工作」模式** | 界面顶部切换控件，选「工作」不选「对话」 | 技能根本不加载，机器人答非所问 |
| 2 | 执行环境是**云主机** | 看环境标识/设置里的运行环境 | 本地电脑会被系统权限拦下载入配置和运行脚本 |
| 3 | 目标账号是**新号**（无历史技能） | 工作台技能列表里没有 `doubao-ecommerce-data-bot` | 新旧版本混装，行位/文案对不上，排查极难 |

> 条件 1 是最常踩的坑：豆包「对话」模式和「工作」模式是两套技能加载机制，自定义技能（`.user_skills`）**只在「工作」模式注入**。装完在「对话」里问它，它一定不认识。

## 2. 装技能

### 2.1 先确认远端默认分支（一次性）

打开仓库设置确认默认分支是 **`saas-tencent`**：

```
https://github.com/Leozhangshouhai/doubao-ecommerce-data-bot/settings/branches
```

**判据**：如果默认分支还是 `main`，安装时**必须手动选 `saas-tencent`**。`main` 是个空壳（`a863ec2`），装上去什么也没有。

### 2.2 安装

1. 工作台 → 技能 / 添加技能 → 从 GitHub 安装
2. 填仓库地址：
   ```
   https://github.com/Leozhangshouhai/doubao-ecommerce-data-bot
   ```
3. 如有分支选择 → 选 **`saas-tencent`**
4. 确认装到**云主机**环境

### ✅ 步骤判据

装完在「工作」模式下问：

> **你是 QPWY 机器人吗**

**预期回答**：自称「QPWY 机器人（配置驱动的电商数据机器人）」，并能说明自己管 4 张报表。

**失败表现**：答"我是一个 AI 助手" / 反问你在说什么 → 技能没加载，回 §1 检查模式和分支。

## 3. 让机器人报一次"我有什么"

不传 yaml，先问它自身能力：

> **你有几个报表？都能出吗？**

**预期回答**：固定 4 张报表，全部标"可出"：

| # | 报表 | sheet 结构 |
|---|---|---|
| ① | 卖断货 | 3 页：一眼看懂 / 今日必盯 / 全量名单 |
| ② | 爆卖 | 3 页：规则总览 / 规模爆品 / 速度爆品 |
| ③ | 热品预判缺货 | 3 页：一眼看懂 / 自营补货清单 / 热品清单 |
| ④ | 供货缺货 | 2 页：前 20 供商 / 前 20 缺了什么 |

**失败表现**：说只有 2 张、或说 ②③"建设中" → 装的是旧版本，分支选错了，重装。

> 这一步很关键。它能在**没有 yaml** 的情况下验证技能本体是否是新版，比直接传 yaml 试错快得多。

## 4. 传配置文件

### 4.1 准备 yaml

从你这拿模板，或让机器人给你模板。**只需要改 9 项**，其余（tunnel / caliber / tables / reports / style）一律不动。必填项与老板版 SOP 第 2 节一致（`customer`、`conn.mode`、跳板机三项、两个内网 target、`db.user`、`db.password`）。

**文件名必须严格是 `ecommerce_bot.yaml`**，改个名就会直接被拒。

### 4.2 上传 + 校验

拖进对话框，说：

> **这是我的配置文件，帮我校验一下能不能用**

### ✅ 校验通过的表现

机器人逐项报「格式 ✓ / 必填项 ✓ / 连接 ✓ / 两个库读表 ✓」，然后问：

> **要不要每天早上自动出报表？几点？**

**这一问是判断"校验真的过了"的最好信号**——没通过不会问时间，会报具体错项。

### ❌ 常见失败与定位

| 机器人说 | 真实原因 | 怎么修 |
|---|---|---|
| `文件名必须是 ecommerce_bot.yaml` | 名字改了 | 改回来 |
| `db.password 还是占位符` | 密码位没换 | 换成真实只读密码 |
| `连接失败：账号或密码错误` | 凭据错 | 找运维核实，**别自己猜** |
| `端口不可达` | 跳板机/内网地址错或隧道没开 | 找运维确认 |
| `表不存在` | 表名与实例不一致 | 要正确表名，写进 yaml |

⚠️ **如果校验失败，机器人必须直接报错，不许自己找环境里的别的配置去补**。这是硬规则（凭据唯一来源 = 本次上传的 yaml）。如果你看到它"自己好了"，那是 bug，要报回来。

## 5. 先别设定时，手动跑一遍四张表

**验收一定要先手动跑，再建定时。** 定时任务出问题时你分不清是脚本错还是调度错。

按顺序说下面四句，每句等它出完再下一句：

| 顺序 | 你说 | 预期关键输出 |
|---|---|---|
| 1 | **出今天的卖断货报表** | 断言打印条数（11-08 基线 1,609），三页 |
| 2 | **出今天的爆卖报表** | 三页，规模/速度两榜条数（基线 101 / 34） |
| 3 | **出热品预判缺货报表** | 断言打印 `自营 N｜其他 M｜合计 T`（11-08 基线 `209｜426｜635`） |
| 4 | **出供货商快缺货** | 两页，20 家供商 |

### ✅ 每次都要核的三件事

1. **sheet 数量与名称** 对上 §3 的表
2. **断言打印的条数** 与页面实际行数一致（自营页 = 自营数 + 3 行表头前区；热品页同理）
3. **交付物是 xlsx**，不是 JSON、不是在线表链接

### ⏱ 耗时参考（别以为是卡死）

| 报表 | 11-08 实测 |
|---|---|
| ① 卖断货 | 227 秒 |
| ② 爆卖 | 数十秒 |
| ③ 热品预判 | **105 秒**（含 ABCD 等级的历史月销额查询，加等级前是 39 秒） |
| ④ 供货缺货 | 数十秒 |

③ 慢是正常的：它要按 `sku_code` 分批（每批 400 个）查历史月销额。别中途打断。

## 6. 交叉校验（每次跑完必做）

这是这套报表最容易被忽略、但最能证明口径没歪的一步：

> **把 ① 的售罄名单和 ③ 的预警名单取交集，必须是 0**

理由：③ 只收"还有货但撑不住"的品，① 只收"已经断了"的品。**同一个商品不可能同时出现在两张表里**。交集不为 0，说明 `is_sold_out` 判据被改过，两张表已经不同步了（历史上出现过 12 个矛盾）。

第二项：**③ 的自营页 + 热品页条数之和 = 封面预警总数**。对不上就是分页归属逻辑出错（`provider_id=0` 归自营、非 0 归热品）。

## 7. 建定时任务

校验通过、手动四张都跑通之后，再回答时间：

> **每天 8:30**（或你要的时间）

### ✅ 预期

- **一个**任务，包含全部四张表，不是四个任务
- 到点一次跑完、一起发
- 说"把定时改成 X 点" / "取消定时"能改能撤

**失败表现**：建了 4 个任务 / 每张表各推一次 → 重复推送、互相覆盖内容，要删掉重建。

## 9. 五个最容易误判为 bug 的现象

| 现象 | 是不是 bug | 说明 |
|---|---|---|
| 报表日期是昨天 | ❌ 不是 | 库存每天 **23:50** 同步，上午看到的必然是前一天 |
| ③ 只有 2 类供商（自营 + 百世鼎盛） | ❌ 不是 | 全站 89 家只有这 2 家库存是真件数，其余 87 家写 `10000` 占位、算不出可售天数。封面有橙色覆盖声明写明了 |
| ③ 报了几百条"快断"但实际没断 | ❌ 不是 | 模型是"日均×天数"外推，对边卖边补的品天然失效。它的价值是**按紧急度排队**，不是预测断货日 |
| ③ 可售天数出现 1,500 天、3,000 天 | ❌ 不是 | 云仓库存占位值的正常表现，业务上"要么有货很多、要么无货" |
| 商品名称/供商名后面有「（云仓）」 | ❌ 不是 | 真实供商名就带这个后缀，脚本用字符类正则兼容了全角半角混写 |

## 10. 装垮了怎么回滚

1. 工作台卸载 `doubao-ecommerce-data-bot`
2. 确认技能列表已无此项
3. 重新安装，**这一步一定核对分支**
4. 重装后先做 §3 的"你有几个报表"，再做后面的

**不要**在旧版本基础上打补丁——脚本、样式契约、SQL 模板三者是成套的，混版本会出现"行位对得上但列数对不上"这种极难查的问题。
