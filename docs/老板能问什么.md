# 老板用：这个机器人能查什么、查不了什么

> 原则只有一条：**有的如实给，没有的直接说没有**。不会猜、不会凑。

---

## 一、四张固定报表（每天自动发，也能随时要）

| 想要什么 | 说一句 |
|---|---|
| 已经卖断的品 | 出卖断货报表 |
| 卖得又快又多的品 | 出爆卖报表 |
| 还有货但快撑不住的品 | 出热品预判缺货报表 |
| 哪个供商缺货最多 | 出供货商快缺货 |
| 四张全要 | 四张都发我 |

---

## 二、能追问的（都在已有四张表的口径里，不另算）

- **按范围**：只看 A 类 / 只看某个供商 / 只看流通品或非流通品 / 只看自营
- **按时段**：昨天的、这一周的、某个具体日期（在库存记录覆盖范围内）
- **问数量**：断了几家、A 类几个、这家供商断几个、比昨天多还是少
- **问单个商品**：某个商品断几天了、现在还剩多少、日均走多少、大概哪天断
- **问结构**：断货集中在哪几家供商、哪几个类目（客户与品牌维度暂未做成固定口径，问起会直说"这个还没做成报表"）

> 要「一份能转发的清单」→ 出固定表；只要「一个数」→ 对话里直接答，不出文件。

---

## 三、查不了的（问起会直接说「这块没有」，可选替代方案）

| 你可能会问 | 回答 |
|---|---|
| 这个月赚了多少、毛利多少 | 大部分商品没有进货价，算不出利润。能给的是卖了多少货、多少件 |
| 运费花了多少、促销活动效果 | 这两项在系统里不记录（全为 0），算不了 |
| 哪个区域、哪个渠道卖得好 | 系统只有一个区域、一个渠道，分不开 |
| 临期品还有哪些 | 数据齐全（3 万多个品有保质期和到期日），但报表还没做，暂时给不了；要做得单独安排 |
| 仓库怎么作业、出入库流水、库位批次 | 系统里只有仓库名称，没有作业记录 |
| 排货、排线、运输时效、司机车辆承运商 | 一条数据都没有 |
| 应收应付、账期回款、对账核销 | 系统里没有这些数据（95% 是货到付款，属正常模式，不是欠款） |
| 下单后供商几天能到货 | 没有采购单和入库记录，推不出到货周期；只知道一次最少订多少 |
| 某个云仓商品还剩多少件 | 云仓库存不记真实件数（统一写 10000），只有「有货 / 断货」两个状态可信 |

---

## 四、两个时间边界（免得判断错）

1. **库存记录从 2026-11-03 才开始累积**。所以「连续断了几天」「这一周断几天」只能算到那天为止；看到 `≥N天` 就是记录只到那里，不是没算。
2. **订单历史约 3 年**（2024 年 1 月起）。所以销量、客户、品牌、类目的历史趋势能看长的。

---

## 五、问不出结果时，机器人会这么说

- 数据里没有 → 「这块数据里没有」+ 给一个能替代的
- 要改数据 → 「我只读，改不了，得在后台操作」
- 算不出 → 说清为什么算不出，不硬给一个数
- 猜不到的原因 → 「原因数据里看不到」，不编理由
