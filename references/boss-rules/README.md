# 老板规则库（boss-rules）

> 装老板长期用出来的**规则**，不装聊天记录。
> 这是给「把老板豆包里的上下文抽象进机器人」准备的容器。现在还没有条目，只搭好了结构和流程。

## 一、三条铁律

1. **只收规则，不收聊天记录。** 一段对话进不来，只有从对话里抽出来的单条规则能进。
2. **每条规则必须能指回老板原话。** 没有出处的规则不许写进来。
3. **老板新说的规则默认进「待确认」。** 交付方确认后才算生效。

## 二、规则状态机

| 状态 | 含义 | 能不能用于出表 |
|---|---|---|
| **已生效** | 交付方确认过，可以照用 | 能 |
| **待确认** | 老板说了，还没确认 | **不能**，只用来理解老板在问什么 |
| **已废止** | 被后来的规则替换 | 不能 |

## 三、冲突优先级（写死，不许现场判断）

1. **已交付口径 > 本 SKILL 正文 > 老板口述规则**
   （`sql_templates/`、`references/style-contract.md` 定的是已封板的口径，优先级最高）
2. **同主题，后说的覆盖先说的**（以规则记录日期为准，不看谁说的）
3. **判断不了** → 不问老板，按已交付口径执行，记一行日志

**为什么这么定**：老板随口一句不能改掉已经封板的口径。口径一漂，四张表就互相打架，比答不上来更糟。

## 四、文件分工

| 文件 | 装什么 | 影响取数吗 |
|---|---|---|
| `口径类.md` | 什么算断货 / 什么算热销 / 哪些类目算流通 / 怎么算天数 | **是** |
| `说法类.md` | 老板习惯的叫法、禁用词、要用的说法 | 否，只影响表达 |
| `待确认.md` | 老板新说的、还没确认的 | 否（不允许用） |

## 五、材料从哪来（三条途径，都要老板点头）

| 途径 | 怎么拿 | 注意 |
|---|---|---|
| 老板直接口述 / 给文档 | 他说，或他把整理好的规则文档给你 | 最干净，优先用这条 |
| 老板在豆包里的历史会话 | 用会话读取能力按会话 ID 取（`im_list_conversations` → `im_get_conversation_messages`） | **必须老板本人授权**；只抽规则，不存原文；抽完把对话内容不要落盘 |
| 截图 / PDF / 表格 | 当作材料读，抽规则 | 抽完只留规则条目 + 出处摘要，不留原图 |

**抽的时候只做一件事**：把材料里的"规矩"挑出来，写成一条件一条的规则。挑不出规则的段落直接丢，不要整段搬。

## 六、导入流程（每次老板给了新材料，照这个走）

1. **读原始材料**（对话 / 口述 / 截图 / 文档）
2. **四类分拣**，别混：
   - 口径 → `口径类.md`
   - 说法 → `说法类.md`
   - 事实（这个库里有什么、没什么）→ `knowledge.md`，**不进本目录**
   - 一次性指令（「明天帮我出个表」）→ **丢掉**，不是规则
3. **写成规则条目**（用下面模板）
4. **标出处**：哪次对话、哪天、原话摘要
5. **进 `待确认.md`**
6. **交付方确认** → 移到 `口径类.md` 或 `说法类.md`，状态改「已生效」
7. **与旧规则冲突** → 旧规则标「已废止」，写明被哪条替换，不直接删

## 七、规则条目模板

```markdown
### R-001 一句话规则（不超过 40 字）
- 状态：待确认
- 出处：2026-11-XX 老板对话，原话摘要
- 影响：取数 / 说法 / 无
- 生效条件：什么情况下用这条
- 老板原话：
  > 原文照抄，不改写
```

## 八、禁止

- 整段对话塞进来
- 写没出处的规则
- 老板说的直接当已生效
- 用「待确认」里的内容出表
- 把「事实」写进本目录（事实归 `knowledge.md`）
