## 1. 三层对账怎么对字段

| 层 | 白话 | 用哪列 | 不要用哪列 |
|----|------|--------|------------|
| ③ 我们定了多少 | 采购单上还没收完的箱数 | 明细 `qty` − `receive_qty`；头 `status IN (3,4,5)`；明细 `is_valid=1` | 不要用 oms 订单；不要把 status 6 收完单算进来 |
| ③ 哪天定的 | 开单日 | 头 `created_at`（int，unix 秒，按 `+08:00` 切） | **不要用 `delivery_at` 当预计到货** |
| ③ 早班该对哪几张 | **近 60 天仍未关的单**（status 3/4/5） | `created_at >= 今天-60 天` | **不要用「当天新建」**：早班 6 点对的是前几天定的货；2026-11-23 17:00 实测当天新建 = 0 |
| ② 仓库实收了多少 | 已经点进系统的箱数 | 明细 `receive_qty`；收货单 `ibd_*` | 卸货当下若还没入系统，库里是 0 |
| ① 供商声称送来 | 预约送货箱数，或纸上的数 | VRM `reservation_detail.delivery_qty`；纸上数字要识图 | PO 的 `delivery_at` 不是「送来多少」 |

`delivery_at`：**datetime**，收货成功时写入当时时间（代码写 `receive_date`，**库里无该列**）。空 = 这张单从没收过货。

## 2. 采购单头 `purchase_order_head`

一张单一个 `po_id`（**核库：po_id 唯一、无重复**；总行数是时点快照，随新增单漂移，不写死）。

| 字段 | 白话 |
|------|------|
| `po_id` | 采购单号。形如 `20261030006267`，前 8 位是开单日 |
| `vender_id` | 供商编号 |
| `vender_name` | 供商名称（对纸、对人用这个） |
| `vender_reference_code` | 供商自己的参考号，可空 |
| `warehouse_code` | 收货仓库 |
| `owner_id` | 货主（自营/寄售等，列表上的货主名来自关联） |
| `purchaser` / `purchaser_uid` | 负责采购的人 |
| `status` | 单状态，见下表。**只在头表，明细没有** |
| `total_qty` / `real_qty` | 整单订货箱数 / 已收箱数（decimal） |
| `total_amount` / `real_amount` | 订货金额 / 已收金额 |
| `is_gift` | `1` 赠品单，`2` 否（核库样板单 20261002006189 是 `1` 赠品单） |
| `is_prepay` | `1` 预付款，`2` 否 |
| `so_id` | 有时关联销售单（按单采购），可空 |
| `comment` / `address` | 备注 / 地址 |
| `created_at` / `updated_at` | **int，unix 秒**。「哪天定的货」切 `created_at` |
| `delivery_at` | **datetime，最后一次收货时间。不是预计到货日。** 可 NULL |
| `venderId` | 与租户/货主有关的冗余列，对账不要当供商 ID 用，供商用 `vender_id` |

### status（代码 `$PO_STATUS` + 前端文案）

| 值 | 列表上写 | 白话 |
|----|----------|------|
| 1 | 草稿 | 还没提交 |
| 2 | 待审核 | 内部还没批 |
| 3 | 待预约 | 代码注释也叫「供商待确认」。有效订货，还没约送 |
| 4 | 待收货 | 可以收，还一箱没收 |
| 5 | 部分收货 | 收过，没收完 |
| 6 | 收货完成 | 这张单收完了 |
| 7 | 作废 | 作废 |
| 8 | 审核驳回 | 驳回 |
| 9 | 供商拒绝 | 供商拒了 |
| 10 | 预付款待审核 | 预付还没过 |

**核库现状（2026-11-23 17:00 时点快照；行数/完成单数会随新增单漂移，口径以 status 枚举为准）**：1 草稿 8｜3 待预约 13｜4 待收货 1｜5 部分收货 106｜6 收货完成 5918｜7 作废 164。合计 6210（17:34 复核为 6211，完成 5919，均为增量漂移）。
未关单 3+4+5 = **120 张**（稳定口径，不受新增完成单影响），按年：2020 10｜2021 44｜2022 18｜2023 9｜2024 16｜2025 11｜2026 12 —— **不能整包当「今天早班」**。

## 3. 采购明细 `purchase_order_detail`

一行一个商品。有效行必须 `is_valid=1`（删行是改成 2，不是物理删；17:00 核库 66096 有效 / 209 已删，17:34 复核 66099 有效，有效行数随新增单漂移，已删 209 稳定）。和头用 `po_id` 关联。

| 字段 | 白话 |
|------|------|
| `po_id` / `line_no` | 所属采购单 / 行号 |
| `goods_id` | 商品编码。**核库全部 18 位左补零**（`000000000001001079`）。和卖断货 `item_id`（`1001079`）对时要去前导零再比 |
| `goods_name` / `bar_code` | 商品名称 / 国条（纸上有条码优先拿国条对） |
| `purchase_unit` | **箱规编码**，实测取值 `H04`/`H06`/`H10`/`H12`/`H15`/`H16`/`H18`/`H20`/`H24`/`H30`/`H50`/`H100`（H 后面是每箱件数，可能两位或三位），**不是中文「一箱几瓶」**。数量单位是**箱** |
| `qty` | **订了几箱**（应收） |
| `receive_qty` | **已经收了几箱**。待收货时常为 0 |
| `qty - receive_qty` | **缺口**。>0 才是还没到齐 |
| `price` / `amount` / `tax` | 含税单价、行金额、税率。门口对箱数用，不对价 |
| `is_gift` / `is_valid` / `comment` | 赠品行 / 1 有效 2 已删 / 行备注 |

## 4. 收货单 `ibd_head` / `ibd_detail`

仓库每收一次，会生一张收货单（入库 IBD）。**核库体量：`ibd_head` 8,784,860 行（≈878 万）、`ibd_detail` 8,880,424 行（≈888 万）——任何查询必须带 `relation_order_no`（对应 po_id）、`warehouse_code` 或时间条件，禁止裸扫全表。**

| 字段 | 白话 |
|------|------|
| `ibd_id` | 收货单号（bigint） |
| `relation_order_no` | 一般是对应的 `po_id`（varchar，注意与 numeric `po_id` 比对时转字符串） |
| `warehouse_code` | 哪个仓收的 |
| 明细 `goods_id` / `goods_name` / `bar_code` | 收的哪个品 |
| 明细 **`qty`**（decimal） | 收货数量。**明细里没有 `pack_qty` 这一列（原稿有误，核库已正）**；箱/件口径看同行 `pack_unit`（varchar，箱规）与 `unit`（char，单位） |
| 明细 `surplus_qty` / `goods_map` | 余数 / 换算数（换算件数时用，别拿 `qty` 当件） |
| 头 `is_del` | 删除标记，查的时候要排除已删 |

② 层「系统里已经点收」看 IBD + PO 的 `receive_qty`。卸货口刚到、还没点系统时，这两处都还没有今天的数。

## 5. 预约（VRM，同实例 `lsh_cx_vrm_saas`）

| 表 | 白话 |
|----|------|
| `reservation_list` | 哪家供商、哪天、哪个仓、约了几箱（`box_qty` / `delivery_box_qty`）。`date` / `begin_at` / `end_at` 是 **int，unix 秒**，不是日期字符串 |
| `reservation_detail` | 哪张 PO、哪个 `goods_id`、预约送 `delivery_qty` 箱 |

**核库结论（2026-11-23）：`reservation_list` 0 行、`reservation_detail` 0 行 —— 预约功能当前没人用，① 层没有电子数，只剩纸面数。** 因此三层对账现在实际只有 ③（PO）和 ②（IBD）两层可自动对，① 层写「无预约数据」而不是 0。

## 6. 和卖断货字段怎么对应（不要混库硬 JOIN）

| 采购这边 | 卖断货那边 | 注意 |
|----------|------------|------|
| `goods_id`（18 位左补零） | `item_id` | 去前导零再比，先抽 5 个品对一下 |
| `vender_id` / `vender_name` | `provider_id` / `provider_name` | 不一定同一套 ID |
| `bar_code` | `goods.bar_code` | 国条对纸最稳 |
| `qty` **箱** | 库存 `total_qty` **件** | **单位不同，不能直接减** |

卖断货连 18/49 用 `agent`；采购连 31 用 `reader`。两套 yaml 不要混着用写账号。

## 7. SKILL 硬规则（取数时照做）

1. 只读：`reader` 或 `agent`。禁止 `writer`。
2. 订货清单默认：`status IN (3,4,5)` + `is_valid=1` + `qty > receive_qty`。
3. 「每天」必须再切 `created_at`（或业务另定的最近 N 天）。未切日期 = 把 2020 年挂账单算进去。
4. 查询前 `SET time_zone = '+08:00'`。`created_at`/`updated_at` 用 `FROM_UNIXTIME`。
5. **禁止把 `delivery_at` 解释成预计到货。**
6. **采购/库存单位不同：采购是箱、库存报表是件，不许混算。**
7. **IBD 是 878 万行大表，必须带 po_id/仓/时间过滤，不许裸扫。**
8. 探表未完成前禁止自写生成器、禁止出正式报表。
9. 对账结果只给人看，不写回收货单、不改 `receive_qty`。

## 8. 「每天订货」口径（2026-11-23 核库已定）

| 切片 | 核库结果 |
|------|------|
| 未关单（3/4/5）且开单 ≥ 2026-10-01 | **仅 2 单**，都是 status 5：10-02、10-30 |
| 11-10～11-22 每天新建（不限 status） | 共 **25 单**（3/2/0/1/0/5/1/2/0/6/3/1/1），工作日 1～6 张；11-12、11-14、11-18 为 0 |
| 11-23 当天新建 | **0 单** |
| 近 60 天未关单 | **2 单** |

结论：

1. **早班应收（门口打勾的第 ③ 层）** = 近 60 天 `status IN (3,4,5)` + `is_valid=1` + `qty > receive_qty`。不要切「今天 created_at」。
2. **近日订了什么（含已收完）** = `created_at` 最近 14 天、不限 status。用来看进货节奏，不是早班缺口。
3. 新单大多很快变成 status 6；所以「还没收完」会远小于「这几天开过的单」。
