# 样式契约（业务报表·模板样式保真）

> 来源：QPWY 导出模板 `03-卖断货-重点关注商品_优化预览_10-10.xlsx`（客户提供，勿覆盖）+ 经验块 `excel-template-style-fidelity.md`。
> **硬规则：任何业务报表 XLSX 生成必须完整套用本契约，禁止从零自拟配色；交付前必须 openpyxl 回读 + 渲染双验证。**

## 适用范围（最高优先级硬规则）

- **固定报表（①卖断货 ②爆卖 ③热度 ④供货缺货）**共用下面的字体和色板，禁止自拟配色。
  页、列、标题锁在**该报表自己的基线**上，不能串页：
  - ① 卖断货：本文件「布局」「明细 10 列」，脚本 `scripts/report_soldout.py`
  - ④ 供货缺货：本文件「④ 供货缺货」，脚本 `scripts/report_supply_short.py`。不要改回卖断货那 10 列
  - ② 爆卖：本文件「② 爆卖（三 sheet）」，出表器 `scripts/render_hot_sale.py`
  - ③ 热品预判缺货：本文件「③ 热品预判缺货」，出表器 `scripts/render_predict.py`。**三分 sheet（一眼看懂 / 自营补货清单 / 热品清单），14 列**
  - 与该报表基线不一致 = 缺陷，必须回归修复
  - **禁止 AI 现场自写生成器**（自写必然导致数据口径或样式漂移）
- **自定义输入（第 5 个入口，非固定报表）**：样式可自定义，按老板要求灵活设计，**不受本契约约束**；
  但数据正确性仍须回读校验（条数、金额、口径与来源一致）。
- 判断标准：**只要是固定 4 报表之一 → 锁定模板；只要走自定义输入 → 可灵活。**

## 字体

- 全表：**Microsoft YaHei（微软雅黑）**
- 标题：16 号加粗 #111827
- 副标题：10 号 #6B7280
- 表头：11 号加粗，深底 #1F2937 白字居中
- 明细：10-11 号

## 统一网格（四张固定报表共用，禁止各写各的）

**硬规则：①②③④ 的明细页必须刷满同一组细网格，线色 `E5E7EB`、`style="thin"`。**

- 范围：表头行 ~ 最后一条数据行，覆盖全部有效列（不按 `max_column` 推，按该报表的列定义）
- 只刷 `border`，**不改填充、字体、对齐、数字格式**
- 合并单元格行不能刷（`MergedCell` 不接受赋值），按合并区域外侧处理即可
- 封面页只给「供商 TOP / 清单构成」这类小表刷，四色块和说明文字区**不刷**
- 规则总览 / 规则说明页**不刷**（整页是文字块，加网格反而碎）
- 统一实现：每个出表脚本里一个 `paint_grid(ws, r1, r2, c1, c2)`，常量 `GRID = Border(left=SIDE, right=SIDE, top=SIDE, bottom=SIDE)`、`SIDE = Side(style="thin", color="E5E7EB")`
- 现状：`report_soldout.py` / `render_hot_sale.py` / `render_predict.py` / `report_supply_short.py` 四处已全部落地
- **禁止**：某张表用深色粗框、某张表无边框、逐行加下划线冒充网格——四张表放在一起必须看不出风格差异

### 入榜判据（样式之外，但必须与表内档位一致）

- 规模：近 7 日 ≥50 件 且 加速比 ≥1.5 且 上涨 ≥3 天
- 速度：近 7 日 ≥10 件（**不设规模上限**）且 近 3 日均 ≥5 且 加速 ≥3 且 上涨 ≥3 且 单日峰值 ≤5×其余 6 日均值（且峰值 ≥10）且 后 3 日无 0 断点 且 非供给恢复型
- 新品：前 4 日 =0 且 前两个可验证快照日有货未断 且 近 3 日均 ≥5 且 后 3 日连续有量 且 末日 ≥ max(第5日, 第6日)×0.6
- 同一商品**允许同时出现在两个 sheet**（规模大的陡品不应被速度榜漏掉）

## ③ 热品预判缺货（自己的基线，色板仍用上面那套）

**3 个 sheet，顺序固定：`一眼看懂` → `自营补货清单` → `热品清单`。**

拆三页的理由（业务结论，不许改回去）：全站 89 家供商里**只有 2 类库存是真实件数**（北京百世鼎盛 7244 键 / 469 种取值 / 10000 占位率 0.5%；自营 pid=0 1410 键 / 480 种取值 / 0.8%），其余 87 家 40%~75% 的库存行写着 `10000` 占位，可售天数会算成 1,500~3,000 天。所以本表拆成「自营（补货决策在内部）」和「供商（需对外下单）」两张清单，各自排序各自打印。

### 页1「一眼看懂」行位（A~D 四列；A=26 宽，B/C/D=16 宽；打印区 `A1:D29`）
| 行 | 内容 |
|---|---|
| R1 | 标题「热品预判缺货 · 一眼看懂」16 加粗 `111827` |
| R2 | 副标 10 号 `6B7280`：「数据日期 YYYY-MM-DD｜热品池 N｜预警 M｜口径 v1.1（热品池 ∩ 可售 ≤20 天）」 |
| R3 | **覆盖声明**（合并 A:D、行高 **30**、9 号加粗 `C2410C`、`wrap_text`）：「覆盖范围：仅库存数据可信的 2 类供商（自营 X + 百世鼎盛 Y）。其余 N 家为云仓占位库存（写着 10000），算不出可售天数，其风险见 ① 卖断货 / ④ 供货缺货。」**这条不许删**，删了老板会把 635 条误读成全站热品风险 |
| R5 | 小标题「按紧急度数量」 |

| R22 起 | 最多 8 家，刷网格 |

7 条说明的固定文案（**每条必须压成单行、≤30 汉字**，A:D 合并宽 58 单位只放得下一行；超出即被下行盖住）：
1. 只收「有货但撑不住」的品；已断的看 ① 卖断货与 ④ 供货缺货。
2. 档位按可售天数：P0≤2 / P1 3~5 / P2 5~10 / P3 10~20 天。
3. 日均已剔除「塌陷日」，避免断货日被推后。
4. 断货日给区间、每天滚动，不是承诺。
5. 3天缺口 = 日均×3 − 库存，够撑 3 天显示 0。
6. 等级 A/B/C/D 与 ① 同口径；同档排序：缺口→等级→日均。
7. 自营页内部补货/调拨；热品页向百世鼎盛下单。

### 页2「自营补货清单」/ 页3「热品清单」（两页列结构与版式完全一致）
- R1 标题 / R2 副标 / **R3 表头 / R4 起数据**；`auto_filter A3:N{末行}`；`freeze A4`
