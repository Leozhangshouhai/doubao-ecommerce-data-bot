# doubao-ecommerce-data-bot

**配置驱动的电商数据机器人（Skill）** —— 面向泛电商老板（零售/批发/供货）：老板不写 SQL、不碰代码，上传一份固定命名的配置文件后，开口说人话即出报表。

> 样板客户：QPWY（全品无忧）。卖断货口径 v1.4 已定稿并验证（1588 条名单，与后台导出 100% 一致）。

## 能力

产品名：**QPWY机器人**。老板入口**固定 4 个报表 + 自定义输入**，不扩充、不超编。

| 编号 | 报表 | 状态 |
|---|---|---|
| ① | 卖断货（哪些品卖断货了） | ✅ 已开通 |
| ② | 爆卖（哪些品卖爆了） | 建设中（仅入口） |
| ③ | 热度（哪些品热度高） | 建设中（仅入口） |
| ④ | 供货缺货（哪些供商缺货） | 建设中（仅入口） |
| — | 自定义输入（不是报表） | ✅ 只读分析 |

## 快速开始

> 📘 **给老板的傻瓜式操作手册**：[老板使用 SOP v1.0](docs/老板使用SOP.md)（第一步干什么、第二步填什么，一步步照着做即可）

### 1. 安装（给 AI 环境装 Skill）

把本仓库 `SKILL.md` 及 `assets/scripts/sql_templates/references` 放入 Skill 根目录（如 `.skills/` 或 `.user_skills/`）。

### 2. 配置（老板一次性操作）

1. 复制仓库内 `ecommerce_bot.yaml` 到本地
2. 填写所有 `<占位符>`：跳板机/直连信息、数据库只读账号密码、表名（默认已给 QPWY 值）
3. **文件名必须保持 `ecommerce_bot.yaml`**，上传给豆包

> ⚠️ 该文件含连接凭据：仅保存在老板自己电脑/私密会话，**严禁上传本仓库或外发**。仓库内只提交占位符模板。

### 3. 使用（老板日常）

- 「出今天的卖断货报表」→ 自动：校验配置 → 连接自检 → 目标日=最新快照 → 模板样式 XLSX + JSON + 一句话解读
- 「卖断货只看 A 类」「按供商排 TOP」→ 条件参数直接生效
- 其他需求直接描述（如「近 7 天 A 类变化」）→ 只读分析

## 架构

```
├── SKILL.md                  # Skill 定义：触发词 + 流程 + 安全约束
├── ecommerce_bot.yaml        # 配置模板（固定文件名，占位符版）
├── scripts/
│   ├── load_config.py        # 配置加载 + 校验 + 连接自检（--check-conn）
│   ├── health_check.py       # （预留）就绪报告
│   └── report_soldout.py     # （改造自 QPWY qpwy_soldout.py）卖断货报表
├── sql_templates/
│   └── soldout.yaml          # 卖断货参数化 SQL 模板（口径 v1.4）
└── references/
    └── style-contract.md     # 报表样式契约（模板保真）
```

### 配置驱动原理

- **口径/SQL 与代码解耦**：SQL 模板参数化（`{date}` `{on_sale_status}`），表名/阈值由 `ecommerce_bot.yaml` 声明，客户不同只改配置
- **校验先行**：`load_config.py` 对文件名校验、必填字段、端口、占位符、连接可达性逐项检查，错误定位到字段，不静默降级
- **只读原则**：全程 SELECT，账号为只读权限

## 安全

- 凭据只存在于老板本地上传的 `ecommerce_bot.yaml`，不进仓库、不进日志
- 本仓库任何 commit 不得包含真实密码/密钥（.gitignore 已排除）
- 数据访问只读；敏感操作一律禁止
