# doubao-ecommerce-data-bot

**配置驱动的电商数据机器人（Skill）** —— 面向泛电商老板（零售/批发/供货）：老板不写 SQL、不碰代码，上传一份固定命名的配置文件后，开口说人话即出报表。

> 样板客户：QPWY（全品无忧）。卖断货口径 v1.4 已定稿并验证（与后台导出逐条核对一致）。

## 能力

产品名：**QPWY机器人**。老板入口**固定 4 个报表 + 自定义输入**，不扩充、不超编。

| 编号 | 报表 | 状态 |
|---|---|---|
| ① | 卖断货（哪些品卖断货了） | ✅ 已开通（口径 v1.4） |
| ② | 爆卖（哪些品卖爆了） | ✅ 已开通（规模榜 + 速度榜 + 规则总览，三 sheet） |
| ③ | 热品预判缺货（采购提前预警） | ✅ 已开通（一眼看懂 / 自营补货清单 / 热品清单，14 列含 ABCD） |
| ④ | 供货缺货（哪些供商缺货） | ✅ 已开通（连续 2 个库存日，关注分 5/2/1/0.3，前 20） |
| — | 自定义输入（不是报表） | ✅ 只读分析（白话进、白话出，不承诺没做的能力） |

## 每日定时报表（产品标准能力）

**目标：4 张报表最终都由定时任务自动导出，老板不必每天开口。**

- **触发时机**：`ecommerce_bot.yaml` 校验 + 连接自检通过后，AI 主动问一次「要不要每天早上自动出报表？几点？」。老板给时间才建；**没给时间不建、不猜时间**
- **一个任务覆盖 4 张表**：①②③④ 一次跑完，只推 XLSX，JSON 留档不交付
- **禁止按表拆任务**：每张表一个任务会同时段重复跑、重复推送、结果互相覆盖
- **任务名**：老板侧 `QPWY每日报表`；内部运维任务 `QPWY每日链路验证`（含链路验证，不推给老板）
- **凭据**：定时任务 query 只写配置路径 `~/.qpwy_bot/ecommerce_bot.yaml`（`chmod 600`），绝不出现密码/连接串
- **部分失败**：某张表失败不影响其他表，当次结果里单独报哪张失败、原因

### 本机运维任务（开发侧）

每天 **10:00（Asia/Shanghai，云电脑）** 一条任务跑：数据链路验证 → ① 卖断货 → ② 爆卖 → ③ 热品预判缺货 → ④ 供货缺货，四张 XLSX 交付、JSON 留档。固定配置 `/home/user/.qpwy_bot/ecommerce_bot.yaml`（`chmod 600`，文件名为硬约束，不入库、不外发）。

## 快速开始

> 📘 **给老板的傻瓜式操作手册**：[老板使用 SOP v1.2](docs/老板使用SOP.md)（第一步干什么、第二步填什么，一步步照着做即可）

### 1. 安装（给 AI 环境装 Skill）

把本仓库的 `SKILL.md`、`scripts/`、`sql_templates/`、`references/`、`templates/`、`docs/`、`tools/` 整体放入 Skill 根目录（如 `.user_skills/doubao-ecommerce-data-bot/`）。目录结构与仓库保持一致，不要只拷 `SKILL.md`。

### 2. 配置（老板一次性操作）

1. 复制仓库内 `templates/ecommerce_bot.example.yaml` 到本地，重命名为 `ecommerce_bot.yaml`
2. 填写所有 `<占位符>`：跳板机/直连信息、数据库只读账号密码（表名与口径段已写死 QPWY 值，**照用不得改**）
3. **文件名必须保持 `ecommerce_bot.yaml`**，上传给豆包

> ⚠️ 该文件含连接凭据：仅保存在老板自己电脑/私密会话，**严禁上传本仓库或外发**。仓库内只提交去凭据的 `templates/ecommerce_bot.example.yaml`。

### 3. 使用（老板日常）

- 「出今天的卖断货报表」→ 自动：校验配置 → 连接自检 → 目标日=最新快照 → 模板样式 XLSX + JSON + 一句话解读
- 「卖断货只看 A 类」「按供商排 TOP」→ 条件参数直接生效
- 其他需求直接描述（如「近 7 天 A 类变化」）→ 只读分析

### 配置驱动原理

- **口径/SQL 与代码解耦**：SQL 模板参数化（`{date}` `{on_sale_status}`），表名/阈值由 `ecommerce_bot.yaml` 声明，客户不同只改配置
- **校验先行**：`load_config.py` 对文件名校验、必填字段、端口、占位符、连接可达性逐项检查，错误定位到字段，不静默降级
- **只读原则**：全程 SELECT，账号为只读权限

## 安全

- 凭据只存在于老板本地上传的 `ecommerce_bot.yaml`，不进仓库、不进日志
- 本仓库任何 commit 不得包含真实密码/密钥（.gitignore 已排除）
- 数据访问只读；敏感操作一律禁止

## 发布纪律（硬规则）

0. **远端推送必须逐次获得老板明确同意**：AI **不得自行执行任何 `git push`**。开发期一切改动只落本地；老板调试结束后**当次明确点头**，才可推送远端。
   - 本地装（源目录 → 本机已安装 skill 目录）同样需老板明确许可后执行，且只动本机、不涉及远端
   - 未经确认的改动一律停在本地
1. **已发布**：①②③④ 四张报表全部上线，口径与样式已固化。安装请按 **tag** 而非分支（版本钉死，换号对比结果才可复现）
2. **远端分支现实**：推送分支为 `saas-tencent`；远端 `main` 仍是初始空壳，要改默认分支需仓库管理员在网页后台 Settings → Branches 操作（PAT 无 Administration 权限）
3. **封板状态**：SKILL 侧暂定封板，不再迭代；后续改动需重新约定版本号
4. 推送前自查：
   - 资产清单与仓库文件**一致**（历史教训：SKILL.md 声明了 `report_soldout.py` 但仓库缺失，导致 AI 自写生成器、数据样式双漂移）
   - 配置/SQL 模板默认值与真实库结构核对（表名/关联键/时间戳类型）
   - 用同日期基线回归比对：名单逐条一致 + XLSX 逐格 0 差异
